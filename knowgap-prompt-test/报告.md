## 失败用例

### T01 格式不合格，诊断与预期不符

预期：正确，无问题，提示等级 0。

```json
{
  "status": "部分正确",
  "issues": [
    {
      "type": "遗漏",
      "evidence": "3x=15，x=5。",
      "description": "结果正确，但题目要求写出必要步骤，从原方程到3x=15这一步的变形依据没有写出来。"
    }
  ],
  "feedback": "x=5这个结果是对的，但题目要求写必要步骤，你跳过了从3x+5=20到3x=15的说明。",
  "hint_level": 1,
  "hint": "检查一下：原方程左边的“+5”是怎样消失的？这一步需要写清楚两边同时做了什么。",
  "next_question": "请把从3x+5=20到3x=15这一步补上，并说明两边同时进行了什么运算。"
}
```

学生已经写出 `3x=15，x=5。`。模型仍判部分正确，并把整句答案放进遗漏证据。遗漏的 evidence 必须是 JSON null。AI 初评：diagnosis_accurate=false，answer_leaked=false。

### T02 格式不合格，诊断与预期不符

预期：正确，接受先除以 3 的解法。

```json
{"status": "部分正确", "issues": [{"type": "遗漏", "evidence": "两边除以3：x+5/3=20/3，所以x=5。", "description": "从 x+5/3=20/3 直接到 x=5，缺少把 5/3 从左边移走的那一步必要过程。"}], "feedback": "两边同时除以3这一步写对了，但最后一步跳得太快，少了一步必要过程。", "hint_level": 1, "hint": "检查 x+5/3=20/3 变到 x=5 这一步：左边的 5/3 是怎么消失的？中间少写了一个运算。", "next_question": "从 x+5/3=20/3 出发，要单独留下 x，等号两边应同时做哪一步运算？"}
```

AI 初评：diagnosis_accurate=false，answer_leaked=false。

## 最值得改的提示词

原 Prompt 这次没有改。建议加到 v0.2 的对应小节。

1. 在“答案边界”增加硬性禁令：`description`、`feedback`、`hint`、`next_question` 都不得写出学生还没提交的正确数字、单词或最终式。错误说明只说“这一步需要重算”，禁止出现“正确的商是5”“3+2应为5”这类更正值。针对 T13、T14。

2. 在“判断当前进展”增加：参考答案写明接受其他正确解法时，学生已经到达等价结果，状态就是“正确”，`issues` 为 `[]`，不得再要求补中间式。针对 T01、T02。

3. 在“定位主要问题”增加：类型为“遗漏”时，`evidence` 只能是 JSON null，不能引用学生原句。输出前单独检查这一条。针对 T01、T02、T05、M03:3、M04:2、M04:3。

4. 把“理解错误”和“步骤错误”分开写死：学生用句子说出错误规则时（如“3只乘x”“符号不用变”），类型必须是理解错误。步骤错误只用于没有说出规则、但变形本身不成立的情况。针对 M03:1。

5. 在“分层帮助”增加输出前核对：新的主要问题从 1 级重新开始。1 级只指出检查位置，不写出具体运算，例如不说“减去5”或“除以3”。同一卡点到 3 级才给一个下一步，仍不给得数。每轮还要回看历史 hint，不能把时态名称、词形规则分几轮拼成可直接提交的解释。针对 M06:3、M04:2。
