# 后端 B1 · 记忆边界 · 规格

来源：`docs/records/后端-B1-全过程.md` 前两节；不重写代码，不新增事实。

## 一、目标

1. 通用对话不再召回任何学习空间的记忆；学习空间对话只召回本空间和全局记忆，不出现其他空间。
2. 后台整理笔记（`_review`）遇到属于某个 Subject 的对话时，跳过通用 USER / MEMORY 笔记写入。

现有实现里 `ChatStore.relevant_memories` 有第三层 `other:<空间名>` 跨空间补充：本地命中不足 `MIN_LOCAL_HITS` 时，会从其他 Subject 召回同主题误区。通用对话的 `subject_id` 为 `None`，这层会把其他空间当成 `outer`，造成通用对话召回学习空间记忆。

## 二、验收（任务单 B1 原文）

- 新增测试：通用对话里，即使其他空间有相关误区，召回结果也不含任何空间记忆。
- 新增测试：学习空间里只召回本空间和全局记忆，不出现其他空间。
- 新增测试：空间对话触发笔记整理后，通用 USER / MEMORY 笔记不变。
- 原有测试全部通过。

## 三、实现方案

### `backend/app/chat/store.py`

- `relevant_memories` 新增 `include_other_spaces: bool = False`，旧调用不传即默认关闭跨空间。
- `names` 只在 `include_other_spaces=True` 时计算，默认路径不再额外查一次 subjects。
- `outer` 收集条件增加 `include_other_spaces`。
- `chosen` 的补充条件增加 `include_other_spaces`，避免默认路径追加跨空间记忆。
- `scope` 字段保留；`other:` 前缀只在显式 opt-in 时产生。

### `backend/app/chat/service.py`

- `_review` 入口先调用 `conversation_subject(conversation_id)`。
- 属于 Subject 时用 `logger.info` 记录并直接返回，不调用模型、不写 `apply_agent_memory`。
- 返回值结构不变（`None`）。

**明确不改：`_analyze` 未改，`_record_profile` 未动。** 已知边界：空间对话若产生 `profile_ops` 仍可能写通用 USER 笔记；如统筹要求封堵，加一个 subject 判断即可。
