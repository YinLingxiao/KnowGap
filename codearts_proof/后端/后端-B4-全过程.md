# 后端 B4 · web_fetch 网页正文工具 · 全过程

## 一、需求分析

目标是在不重写网页请求和安全逻辑的前提下，为模型增加 `web_fetch(url, focus?)`：先用 `web_search` 搜索拿链接，再用 `web_fetch` 打开原文，回答时只对实际读取成功的网页使用 `[网页N]` 引用。

实现必须复用 `PageFetcher.allowed/fetch`、`safe_url`、`_public_ip`、`html_to_text` 和 `PAGE_CHAR_BUDGET`。localhost、内网、非 HTTP(S)、非 80/443 端口均由既有安全入口拒绝，拒绝前不得发出 HTTP 请求。内部保留 `_fetcher()` 工厂，测试注入真实 `PageFetcher + httpx.MockTransport + 异步假 resolver`，不访问真实网站、真实 DNS 或真实模型。

成功返回 JSON 字符串 `{url,title,text,truncated,chars}`，失败增加 `error`。`chars` 是截断前正文的 Python 字符数；正文超过 6000 字时保留前 6000 字并追加 `…（正文过长，已截断，原文 N 字）`。`focus` 不参与摘要、正文改写或安全判断。

工具可见性与 `web_search` 绑定：thread 同时可见，main、普通 chat 和系统事件回合同时不可见，不全局开放。交付限定三个生产文件、一个新测试文件和本记录；全量测试退出码为 0 才允许提交推送。

## 二、代码生成

- `backend/app/agent_tools/problem_search.py`
  - 新增 `WEB_FETCH_TOOL_NAME`、严格输入模型、成功/失败结果类型和 `WEB_FETCH_DEFINITION`。
  - 新增 `_fetcher()`，生产只返回既有 `PageFetcher()`；测试可在调用时替换工厂。
  - `run_web_fetch` 依次执行参数校验、`allowed`、`fetch`、`html_to_text`、标题提取、截断和 JSON 序列化，没有另写 HTTP 请求或 DNS 判断。
  - 标题只取 `<title>` 的规范化文本；无标题返回空字符串。失败结果不保留部分正文，普通异常不泄露堆栈，`CancelledError` 继续传播。
  - 失败回显地址会去除凭据；`file://`、`ftp://` 等普通输入可回显，但是否放行仍完全由 `PageFetcher.allowed` 决定。
- `backend/app/agent_tools/__init__.py`
  - 在 `DEFINITIONS` 追加一次 `WEB_FETCH_DEFINITION`。
  - `run()` 新增 `web_fetch` 分发并直接返回 JSON，避免通用 `_clip` 破坏长 JSON 和精确截断后缀；其他工具仍走原路径。
- `backend/app/chat/service.py`
  - 只新增 `WEB_FETCH_TOOL_NAME` 导入，并把它加入普通 chat 当前排除 `WEB_SEARCH_TOOL` 的集合。
  - main 白名单、event 允许集合、thread 逻辑和检查点重放清单均未改。
- `backend/tests/test_web_fetch.py`
  - 新增 15 个测试函数，参数化后 37 项；统一通过 `_fetcher` 注入真实 PageFetcher、MockTransport 和假 resolver。
- `docs/records/后端-B4-全过程.md`
  - 新增本记录，保存实际变更、排错和验收证据。

未修改 `web_search.py`、`checkpoints.py`、前端、依赖、数据库、既有测试或 B5 文件。
