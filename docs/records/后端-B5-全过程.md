# 后端 B5 · 通用记忆写入事件与单条撤销 · 全过程

## 一、需求分析

最小版目标：通用记忆被实际写入时推送 `memory_write` 事件，并且能按 `note_id` 撤销本人单条写入。

- `app/memory/curated.py` 的 `apply()` 返回值是给模型看的中文话术，保持逐字不变；新增 `memory_write_log(id, student_id, layer, content, conversation_id, message_id, created_at)`，在既有 `ensure()` 内以 `CREATE TABLE IF NOT EXISTS` 幂等建表，不新建数据库文件、不回填历史文本。
- `apply()` 在参数表最后以独立 `*` 增加仅关键字可选参数 `conversation_id / message_id / events`；只有非待确认且 `add` / `patch` 实际写回后才在同一连接插入日志，并在提供 `events` 时追加严格 `{id, layer, content}` 三项（`user/memory → USER/MEMORY`）。`remove`、重复、校验失败、待确认均不写日志、不追加事件。
- `ChatStore.apply_agent_memory` 透传上述参数并复用同一连接、同一 `now()`；`service._review` 收齐本次实际条目后，仅在非空且有关联在线 `generation` 时 `generation.queue.put_nowait(("memory_write", {"items": [...]}))`，空批次与无在线流不推送、不补播。
- 撤销 `DELETE /api/agent-memory/{note_id}`：只能撤自己的；他人、编造、已撤销（重复撤销）一律 `404 {"detail":"记忆条目不存在"}`。按日志指向的 layer 读取原始文本，按精确分隔符 `\n§\n` 拆分后仅删除完整相等的一个条目再写回，并在同一事务删除日志行；成功返回空 `204`。
- 不碰 `learner_memories`，不改 `PUT /api/agent-memory`、GET/pending 契约、前端与依赖。
- 测试覆盖用户指定五项：写入时事件带条目、撤销后笔记和 log 都干净、别人的 id 404、编的 id 404、重复撤 404。
- 门禁同 B4：保留范围新增失败为零即过，唯一可排除项为既有 `tests/test_agent_regressions.py::test_shell_timeout_and_cancel_stop_descendants[False]`（Windows PowerShell 进程树用例）。

- `backend/app/memory/curated.py`
  - 新增 `MemoryWriteItem(TypedDict)`（`id/layer/content`，`layer` 为 `Literal["USER","MEMORY"]`）。
  - `ensure()` 末尾追加 `CREATE TABLE IF NOT EXISTS memory_write_log` 七列，`layer` 限定 `user/memory`，两个来源字段可空。
  - `apply()` 在 `approve` 后经 `*` 增加 `conversation_id=None, message_id=None, events=None`；`_store()` 之后仅对 `add/patch` 生成 `note-<uuid4 hex>` 并插入日志，`content` 为写入后的完整条目，`created_at` 复用本次 `timestamp`；提供 `events` 时追加同 id 的三字段项。所有既有话术、校验、去重、容量与审批语义未改。
  - 新增 `revoke_applied_note()`：按 `id + student_id` 查日志，未命中返回 `False`；只读日志指向层，原始文本按精确 `SEP` 拆分（不复用会 strip/宽松拆分的 `split_entries()`），无完整相等条目返回 `False` 且不改文本不删日志；命中时删一个目标条目、按 `join_entries()` 写回（唯一条目删除后为空字符串），并同事务删除日志。
- `backend/app/chat/store.py`
  - `apply_agent_memory()` 增加同序仅关键字参数并显式透传，读改写使用 `BEGIN IMMEDIATE`，文本与日志共享一次连接提交。
  - 新增 `revoke_agent_memory(student_id, note_id)`：单连接 `BEGIN IMMEDIATE` 调用 `revoke_applied_note`，只暴露布尔结果；未复用 `save_agent_note()`，未触碰 `learner_memories`。
- `backend/app/chat/service.py`
  - `_start_review()` / `_review()` 增加仅关键字 `generation=None`；`_start_review()` 返回任务对象，旧调用方可忽略返回值。
  - 仅当前 `_run()` 对同会话达到即时复盘阈值时传当前 `generation`；切换会话、空闲、恢复复盘不传，不新增补播。
  - `_review()` 用单次局部 `events` 列表按 ops 原顺序收集，循环结束后仅在非空且 `generation` 非 None 时入队一个 `memory_write`。
  - `_run()` 在 `finally` 的 `queue.put_nowait(None)` 前以 `asyncio.gather(..., return_exceptions=True)` 收束本回合在线复盘任务，后台异常只记日志，不改写已完成回复，保证 `done` 先于 `memory_write` 且事件在流关闭前可读。
- `backend/app/chat/router.py`
  - 只新增 `DELETE /agent-memory/{note_id}`（既有 `/api` 前缀）：`False` 抛 `HTTPException(404, "记忆条目不存在")`，成功显式返回空 `Response(status_code=204)`；无请求体、无批量参数，PUT/GET/pending 未改。
