# 后端 B3 · 六模式 · 全过程

## 一、需求分析

目标：

- `SendMessage` 增加可选 `mode`，六个值：`explain` / `solve` / `practice` / `plan` / `research` / `organize`。
- 不传或 `null` 时行为与原来逐字节一致；非法值由 Pydantic `Literal` 返回 422。
- 每个模式注入自己的提示词；卡片规范按模式收窄，practice 只保留 micro_quiz 的 schema 段。
- 卡片断言只看 schema 段，capability/craft/visual 原样保留；mode 段末尾加硬约束：
  `本模式只使用以下卡片：<widgets 原文>；其它类型一律不要输出。`
- 透传顺序写死：`add_user_message → merge_meta({"mode": ...}) → begin`；`chat_messages` 的 `mode` 是仅关键字参数，放在参数表最后。

已确认的卡片映射：

| mode | label | widgets | 保留卡片（原编号） |
| --- | --- | --- | --- |
| explain | 讲解 | step_simulator,comparison_matrix | 1、2 |
| solve | 解题 | step_simulator,code_playground | 1、4 |
| practice | 练习 | micro_quiz | 3 |
| plan | 规划 | gap | 5 |
| research | 研究 | comparison_matrix | 2 |
| organize | 整理 | comparison_matrix | 2 |

## 二、代码生成

- 新增 `backend/app/chat/prompts/zh/modes.yaml`：六个模式，`label` / `widgets` / `prompt` 全部是字符串，`widgets` 用逗号分隔，未使用 YAML 列表。
- `backend/app/chat/skills/__init__.py`：
  - 新增 `widget_prompt_for(mode)`；`WIDGET_SYSTEM_PROMPT = widget_prompt_for(None)` 保留，mode=None 原样返回旧常量。
  - mode 非 None 时只裁剪 schema：保留 heading、intro、允许的卡片键、constraints；capability、craft、visual 原样保留。
  - intro 的「支持以下 5 种类型」按实际数量替换；卡片编号不重排。
- `backend/app/chat/schemas.py`：`SendMessage.mode` 使用 `Literal[...] | None = None`。
- `backend/app/chat/agent.py`：
  - `chat_messages(..., *, mode: str | None = None)`，mode 放在参数表最后。
  - mode 段位于 context_prompt 之后、widget 段之前；mode=None 不插入任何内容。
  - mode 段末尾追加硬约束句。
- `backend/app/chat/router.py`：`add_user_message` 后、`begin` 前写 `merge_meta({"mode": body.mode})`（仅非 None）。
- `backend/app/chat/service.py`：`Generation.mode`；`begin` 从 `message_meta` 读回 mode；`_run` 传给 `chat_messages`；事件轮传 None。
- `backend/tests/test_modes.py`（新增）；`backend/tests/test_prompt_manager.py` 仅增补两条测试。
- `docs/后端接口约定.md`：mode 状态改为「已实现（B3）」，发布顺序改为前端可以开始传。
- `docs/records/后端-B2-全过程.md`：补「本轮码道未生成新导出；B2 码道导出重复归档已在 B3 删除。」
