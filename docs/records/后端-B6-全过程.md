# 后端 B6 · 多智能体学习规划 · 全过程

## 一、需求分析

B6 在学习空间内提供复习任务草稿与确认写入能力，三个智能体严格串行接力：

1. 诊断 `diagnose`：只从当前学生、当前学习空间、类型为 `misconception` 且状态不为 `resolved` 的记忆中选择该复习的误区，并给出建议复习日期和优先级。
2. 规划 `plan`：把诊断结果转换为带标题、依据、建议时长、计划日期和顺序的候选任务；按 `due` 升序、同日 `priority` 升序、无 `due` 置后排列。
3. 审核 `review`：检查任务依据、重复、日期和总时长。代码规则先形成确定的审核基线，模型只能追加拒绝，不能恢复规则已拒绝的任务；模型审核失败时退回规则结果。

草稿先落库而不直接写日程，是为了把“系统生成建议”和“用户确认执行”分开：生成接口只保存草稿头、三个智能体输出和最终任务快照，用户可以查看并选择；只有确认接口才把选中的服务端快照写入 `agenda_tasks`。这样也避免客户端回传标题、时长、日期或来源篡改审核结果。

硬性边界：模型调用前完整读取数据并关闭连接，`await` 期间不持有连接或事务；每个智能体记录开始和结束日志；总时长不超过请求预算且绝不超过 120 分钟；不改 `chat/store.py` 和前端。

## 二、代码生成

- `backend/app/learning/__init__.py`：学习模块包标记。
- `backend/app/learning/schemas.py`：两个接口的请求、响应、三阶段输出和执行记录模型；使用严格整数、日期、字面量和 `extra="forbid"` 校验。
- `backend/app/learning/agents.py`：诊断、规划、审核三个异步模型入口；通过现有 PromptManager 加载提示词，使用 `asyncio.wait_for` 和 60 秒超时，校验各阶段最低结构。
- `backend/app/learning/service.py`：核心服务层。
  - `ensure` 以 `CREATE TABLE IF NOT EXISTS` 建立 `learning_plan_drafts` 和 `learning_plan_draft_tasks`，可重复执行。
  - `read_snapshot` 在一个短连接内校验空间并读取全部合格误区及证据，退出连接后才允许模型调用。
  - `build_draft` 固定执行诊断、规划、审核，记录六条阶段边界日志；规划任务标识由服务端生成。
  - `review_by_rules` 拦截无依据、非法字段、重复、日期越界和超预算任务；超预算保留最长合格前缀，不从后方补入短任务。
  - `save_draft` 只写学习草稿表；`confirm_draft` 在 `BEGIN IMMEDIATE` 事务内仅插入选中任务，写入 `source=learning_agent`、`memory_id`、`duration_minutes`，并回填确认标识。
- `backend/app/learning/router.py`：挂载 `POST /api/learning/plans/draft` 和 `POST /api/learning/plans/{draft_id}/confirm`。
- `backend/app/learning/prompts/zh/diagnose.yaml`、`plan.yaml`、`review.yaml`：三份中文提示词，均为非空字典和非空字符串，没有 YAML 列表。
- `backend/app/main.py`：只增加学习路由导入与挂载两行，复用现有 `chat` 模型注入。
- `backend/tests/test_learning_plan_draft.py`：新增独立验收测试，使用假模型三段 JSON 队列、独立临时数据库和 `caplog`。

## 三、测试排错

### 用例覆盖

新增的 62 个用例覆盖：

- 三阶段顺序、候选记忆范围、服务端标识、诊断去重及规划排序；空候选仍执行完整三阶段。
- 缺依据、伪造依据、非法标题和时长、重复任务、日期闭区间与无效日期。
- 80/50/10 超预算截断、不补入后方 10 分钟任务，以及恰好 120 分钟通过。
- 规则优先于审核模型；异常、无效结构、未知标识和超时均降级为规则结果。
- 生成不写日程、跨重启确认、选中子集、空/重复/无效选择、防字段篡改、草稿归属隔离。
- 并发确认至多写一条日程，第二次插入失败时第一次插入及确认标记一起回滚。
- 三次模型调用入口活动连接均为 0；成功链路恰好六条有序日志，失败与降级日志可用 `caplog` 检索。
- 非法请求由 FastAPI/Pydantic 返回 422；重复 `ensure` 和重启不破坏既有记忆与日程。

排错中发现确认响应直接把日程整行交给 `LearningAgendaTask`，其 `extra="forbid"` 拒绝日程的其他字段。修复为先筛选公开响应字段再校验，未放宽模型，也未改日程公开来源枚举。
