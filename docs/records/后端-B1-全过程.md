# 后端 B1 · 记忆边界 · 全过程

## 一、需求分析

目标有两条：

1. 通用对话不再召回任何学习空间的记忆；学习空间对话只召回本空间和全局记忆，不出现其他空间。
2. 后台整理笔记（`_review`）遇到属于某个 Subject 的对话时，跳过通用 USER / MEMORY 笔记写入。

现有实现里 `ChatStore.relevant_memories` 有第三层 `other:<空间名>` 跨空间补充：本地命中不足 `MIN_LOCAL_HITS` 时，会从其他 Subject 召回同主题误区。通用对话的 `subject_id` 为 `None`，这层会把所有其他空间都当成 `outer`，造成通用对话召回学习空间记忆。

规则目录 `.codeartsdoer/rule/` 只有 `metadata.properties`（内容 `projectExpert=[]`），没有规则正文；按 `docs/` 与本任务提示词执行。

## 二、代码生成

- `relevant_memories` 新增 `include_other_spaces: bool = False`，旧调用不传即默认关闭跨空间。

- `_analyze`、`_record_profile` 未改。

### `backend/tests/test_memory_boundary.py`（新增）

5 个测试：

## 三、测试排错

### 排错 1：`create_subject` 报 `no such table: course_materials`

测试只用 `Store.initialize()` + `ChatStore.initialize()`，但 `create_subject` 内部统计 `course_materials`。修复：测试夹具增加 `MaterialStore(base).initialize()`，与 `app/main.py` 的初始化顺序一致。

### 排错 2：旧跨空间断言失败

`test_layered_recall_prefers_own_subject_and_looks_outward_only_when_needed` 要求空间对话召回「其他科目：数据结构」。这与 B1 默认关闭跨空间直接冲突，按用户要求先说明后修改。修改后曾试图断言第 6 步精确等于 `[通用偏好]`，但本地「进程调度」记忆因既有词项匹配被召回，属于既有行为；最终只断言“不含其他科目”，不改变本地召回规则。

### 排错 3：全量测试中的 PowerShell 超时
