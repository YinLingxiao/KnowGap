# 后端 B2 · 资料来源标注 · 全过程

## 一、需求分析

目标：

1. 学习空间对话的引用编号区分「空间资料N」与「通用资料N」。
2. 每条引用返回 `source` 字段（`space` / `general` / `null`）。
3. 提示词增加「空间资料与通用资料冲突时，以空间资料为准，并明确说明差异」。
4. 兼容旧消息 `meta_json`：旧引用没有 `source` 时读取不能 500。

经确认的边界：

- `search()` 只填 `source`，label 仍为 `资料`；materials API、cheatsheet、附件路径共用它，前缀变化收益为零。
- 只有 `search_scoped(subject_id 非空)` 做两段编号；自由对话、附件、资料库检索一律沿用 `资料`。
- `thread_worker.yaml` 改为「引用处原样使用 `sources[].label`」，不写死空间资料格式。
- `file_skills.py`、`test_office_readers.py`、`parallel_chat.yaml` 不动。

## 二、代码生成

- `backend/app/models/schemas.py`：`SourceReference` 增加 `source: Literal["space", "general"] | None = None`，默认值兼容旧 meta。
- `backend/app/services/materials.py`：
  - `search()` 的 SELECT 增加 `d.subject_id AS document_subject_id`，按它填 `source`；label 仍为 `资料N`。
  - `search_scoped()`：`subject_id is None` 直接返回 `search(scope=None)` 的中性 `资料N`；非空时空间段编号 `空间资料1..n`，通用补充段编号 `通用资料1..m`。
- `backend/app/chat/agent.py`：`course_sources` 白名单增加 `source`。
- `backend/app/chat/prompts/zh/learning_space.yaml`：引用处改为原样使用 `sources[].label`，并增加冲突规则。
- `backend/app/chat/prompts/zh/thread_worker.yaml`：引用处改为原样使用 `sources[].label`。
- `backend/tests/test_prompt_manager.py`：旧断言 `[资料N]` 改为 `sources[].label`。修改理由：任务单 B2 要求引用编号区分空间资料/通用资料，`service.py:1125` 按 `[source.label]` 精确匹配，提示词继续教 `[资料N]` 会让引用被静默丢弃；旧断言与新验收直接冲突。
- `backend/tests/test_source_origin.py`（新增）：7 个测试。
- `docs/后端接口约定.md`：状态行改为「已实现（B2）」；第 3 节补充适用范围与空段规则。
