## 通用约定

- 消息发送返回 **SSE 流**，不是单个 JSON：每帧为 `event: <事件名>\ndata: <JSON>\n\n`。
- 现有事件包括 `start`、`delta`、`done`、`analysis`、`plan`；B5 新增 `memory_write`。
- 消息对象以 `app/chat/schemas.py` 的 `ChatMessage` 为准，引用列表在 `ChatMessage.sources`。

## 1. 消息请求的 mode

**路径**：`POST /api/conversations/{conversation_id}/messages`（已实现）

### 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `content` | `string` | 是 | 用户输入，1–12000 字 |
| `client_request_id` | `string` | 是 | 幂等/续跑键，8–80 位 `[A-Za-z0-9_-]`；现有逻辑不变 |
| `mode` | `"explain" \| "solve" \| "practice" \| "plan" \| "research" \| "organize" \| null` | 否 | 不传或 `null` 表示通用，行为与现在完全一致 |

语义：`explain` 讲解 · `solve` 解题 · `practice` 练习 · `plan` 规划 · `research` 研究 · `organize` 整理资料。

### 请求示例

```json
{
  "content": "帮我练两道栈的题",
  "client_request_id": "req-20261118-01",
  "mode": "practice"
}
```

### 返回示例（SSE，节选）

```text
event: start
data: {"conversation": {...}, "user_message": {...}, "assistant_message": {...}, "discarded_ids": []}

event: delta
data: {"text": "先来一道小题："}

event: done
data: {"message": {...ChatMessage...}}
```

`mode` 只影响系统提示，不改变 `start` / `delta` / `done` / `analysis` / `plan` 的事件结构；`system_turn`（事件轮）忽略 `mode`。

### 非法值

传枚举之外的值返回 422，由 Pydantic `Literal` 自动产生，例如：

```json
{"detail": [{"type": "literal_error", "loc": ["body", "mode"], "msg": "Input should be 'explain', 'solve', 'practice', 'plan', 'research' or 'organize'", "input": "quiz"}]}
```

### 发布顺序

`SendMessage` 当前是 `StrictModel(extra="forbid")`，且 `client_request_id` 必填。**B3 后端先上线 `mode` 字段，前端再开始传**；前端提前传 `mode` 会收到 422。

## 2. 记忆写入事件与撤销

### SSE 事件 `memory_write`（待实现，B5）

与 `analysis`、`plan` 同级，在通用记忆写入成功之后推送：

```text
event: memory_write
data: {"items": [{"id": "note_7f3a", "layer": "USER", "content": "偏好先看例题再看定义"}]}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | `array` | 本次写入的通用记忆条目 |
| `items[].id` | `string` | 条目 id，撤销时使用 |
| `items[].layer` | `"USER" \| "MEMORY"` | 通用笔记层 |
| `items[].content` | `string` | 条目正文 |

### 撤销（待实现，B5）

**路径**：`DELETE /api/agent-memory/{note_id}`

- 成功：`204 No Content`
- 不存在、或不是当前学生的条目：`404`

```json
{"detail": "记忆条目不存在"}
```

重复撤销同样返回 404；别人的条目与不存在的条目一律 404，不泄露存在性。

### 与现有接口的区别

- `GET /api/agent-memory`：读取 `{"user": "...", "memory": "...", "limits": {...}}`（已实现）。
- `PUT /api/agent-memory`：按 `{"target": "user"|"memory", "content": "..."}` **整段覆盖**（已实现）。
- `DELETE /api/agent-memory/{note_id}`：只删**单条**，不整段覆盖（待实现）。

## 3. 引用的来源字段

**位置**：`ChatMessage.sources[]`，随 `GET /api/conversations/{conversation_id}`、SSE `done` 的 `message`、`analysis` 事件中的消息一起返回。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | chunk id |
| `document_id` | `string` | 文档 id |
| `title` | `string` | 文档标题 |
| `label` | `string` | 学习空间对话：`空间资料N` / `通用资料N`；自由对话、附件、资料库检索：`资料N` |
| `source` | `"space" \| "general" \| null` | B2 起返回；历史消息可能没有，读取默认 `null`，不能报错 |
| `page` | `integer \| null` | 页码 |
| `start_line` | `integer \| null` | 起始行 |
| `end_line` | `integer \| null` | 结束行 |
| `excerpt` | `string` | 命中片段 |

### 编号规则

- 只有学习空间对话（`subject_id` 非空）做两段编号。
- 本空间文档命中记 `空间资料N`，补充的通用文档命中记 `通用资料N`。
- 两段各自从 1 开始、不跳号；本空间无命中、只有通用资料时直接从 `通用资料1` 开始，不出现 `空间资料0` 或空段。
- 自由对话、附件、资料库检索接口一律沿用 `资料N`。
- `source` 字段在以上三种情况下都照常返回。

### 返回示例

```json
{
  "id": "chunk_12",
  "document_id": "doc_3",
  "title": "通信原理 第 3 章.pdf",
  "label": "空间资料1",
  "source": "space",
  "page": 42,
  "start_line": null,
  "end_line": null,
  "excerpt": "…抽样定理…"
}
```

提示词规则（B2 已实现）：空间资料与通用资料冲突时，以空间资料为准，并明确说明差异。

{

      "finished_at": "2026-11-18T10:00:02+00:00",
      "output": {
        "weak_points": [
          {"memory_id": "mem_31", "topic": "栈溢出判断", "summary": "把越界写成溢出", "due": "2026-11-21", "priority": 1}
        ]
      }
    },
    {
      "agent": "plan",
      "started_at": "2026-11-18T10:00:02+00:00",

    {

      "started_at": "2026-11-18T10:00:04+00:00",

约束：

- `agents` 顺序固定为 `diagnose` → `plan` → `review`。
- 每条 `tasks[]` 必须带 `memory_id`（依据）和 `duration_minutes`（建议时长）。
- 生成接口只返回草稿，不写日程。

### 确认写入日程

**路径**：`POST /api/learning/plans/{draft_id}/confirm`

请求：

```json
{"task_ids": ["d1"]}
```

返回：

```json
{
  "created": [
    {"id": "task_5b", "title": "复位栈指针练习 10 题", "source": "learning_agent", "duration_minutes": 30}
  ],
  "skipped": []
}
```

确认是唯一写日程的入口；后端按 `draft_id` + `task_ids` 从存储的草稿取字段，不信任客户端回传的任务内容。写入日程时 `source="learning_agent"`，并带 `memory_id` 与 `duration_minutes`。
