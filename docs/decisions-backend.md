# 后端 MVP 技术决策（2026-10-14）

## SQLite 与原生协调

保留 FastAPI + Pydantic；用 Python sqlite3，不引入 ORM、向量库、Agent 框架。
会话、消息、记忆及证据关联表持久化，外键启用，WAL 支持本地并发读取。
一轮会话写入与记忆变更在同一事务完成；模型调用在事务前，避免网络等待占用写锁。
同一会话的并发提交按 turn 乐观校验，过时请求返回 409；不自动重试收费模型请求。

## 可替换模型接口

Tutor Protocol 将模型接入与业务协调分开。默认适配器为兼容 Chat Completions 的 JSON object 输出。
用 httpx 发请求，不绑定特定提供商 SDK；服务地址、密钥、模型名全部由后端配置。
输出经 Pydantic 校验，再检查 evidence 是否为本次作答的非空连续原文。
错误时返回明确错误，不自动切换成伪造诊断。原文引用校验不能证明教学判断正确，需要真实模型评估。

## 最小记忆治理

只处理经过参考解校验的栈题，topic_key 和 issue_key 由后端控制，不由模型任意生成。
按身份/知识点/误区合并；记忆保留具体消息和题目引用，当前证据优先于历史状态。
提示后的正确只支持改善；两道不同题目在最近错误后的首次正确才支持 resolved。
“首次回答”只是本地演示下独立作答的近似证据，不能验证学生是否参考外部答案。
删除的是可检索记忆及关联，不删除源会话；真正的数据清除功能尚未实现。

## 本地演示边界

仅接受固定演示身份，默认绑定回环地址。CORS 不是认证，不面向公开多用户部署。
模型上下文限制近期 12 条消息、至多 3 条同知识点记忆及每条最近 3 段证据。
原始会话完整持久化；暂不实现 SSE、用户登录、队列题扩展和桌面封装。
