# 主对话协调，Thread 执行

更新：2026-10-16。实现于 main；修改前已 fetch，HEAD 与 origin/main 均为 `2366915`，ahead/behind 为 0/0。工作区此前已有 README、截图与记忆测试等未提交改动，原样保留并在现有 README 上更新相关交互说明。

## 用户流程

1. 用户在空间主对话描述学习需求。简单问题可以当场回答；具体教学、练习和资料研究交给 Thread。
2. 协调 AI 根据空间内已有任务选择新建或续接，立即交办并启动。用户无需点击新建或重新描述需求。
3. 新分派事件展开右侧对应 Thread。用户可以直接在它的输入框里深入交互，也可以回到主对话继续补充。
4. 主对话的关联卡片持续更新该轮的状态、进展和结果。点击卡片可以再次打开 Thread。
5. 侧栏分组：等待你（含失败）、正在执行（含排队）、空闲、已解决。本轮回复完成与整个问题已解决分别表示。
6. 原有“已解决 → 编辑小结 → 合并回主对话”保留，用于正式结束某个问题。

## 服务端

- `dispatch_thread(title, task, thread_id?)` 只提供给主对话；不传 id 时创建，传入本空间 Thread id 时续接。
- `report_progress(summary, needs_user?)` 只提供给 Thread。提示要求重要进展和本轮结束前回报；回复后的学情分析也会提取本轮结果与是否等待用户。若二者均未返回有效回报（例如分析服务不可用），使用实际回复节选作为兜底，并明确标注节选。
- 协调主对话只获得分派、历史搜索和长期笔记工具；文件与命令工具由执行 Thread 使用。工具执行时也校验当前角色允许的工具。
- `thread_dispatches` 在同一事务中保存分派记录、子会话和转交消息。同一用户消息的同一标题或目标 Thread 不重复交办。
- 转交消息保留用户原话；模型的任务说明独立存为 `delegated_task`，不会冒充用户的学习证据。已分派的主对话轮次不重复提取学习证据。
- 一个 Thread 同时只生成一条回复。忙碌时的补充持久化排队，依次启动；每轮只读取截至该用户消息的历史，避免提前处理后来的补充。
- AI 分派的生成任务由服务端独立持有，浏览器切换、关闭或刷新不会取消它；用户可以在侧栏显式停止。停止也取消该 Thread 尚未执行的排队补充。
- 自动执行期间分段保存文本和工具结果，右侧可以读取最新内容。审批信息持久化到回复，刷新后仍能在 Thread 内处理；审批通过后从持有该请求的任务继续。
- 每个工作轮次对应主对话的一张 `thread_update` 卡片，按工作中、等待、完成、失败或停止更新，详细文本留在 Thread。直接在侧栏发送的轮次也回报。
- 服务退出取消运行任务。重启时把中断状态同步到主对话；尚未开始的排队消息恢复执行。已有失败回复不会自动重放，避免重复文件操作。
- 原有 `POST /api/subjects/{id}/threads` 暂保留兼容性，产品界面移除手动创建入口。

## 前端与接口

- 消息增加 `thread_update`、`pending_approval`，会话摘要增加 `execution_status`；原有 `thread_status=open/resolved` 保留。
- 主对话流增加 `thread_dispatched {thread_id}` 事件，用于显示执行 Thread。
- 页面打开期间每 1.5 秒刷新空间任务和服务端生成的消息；本页面直接发起的流式回复不被轮询覆盖，页面隐藏时暂停轮询。
- 主对话练习入口交给 AI 分派，侧栏保留直接练习与输入能力。
- 创建与续接的语义选择由模型决定，服务端验证空间归属、参数与重复分派；语义判断仍可能需要用户纠正。
- 当前后台任务在本地后端进程中执行，并非云任务。关闭浏览器可继续；退出后端或电脑休眠会中断，不能承诺关机后继续。
