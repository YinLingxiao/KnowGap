## 实测结果

模型列表请求返回 HTTP 200，可用模型为 deepseek-flash、deepseek-v4-pro。
六次生成调用均返回 HTTP 200；五次诊断的判定与测试预期一致。

| 场景 | HTTP | 判定 | 记忆状态 | 耗时（秒） |
| --- | --- | --- | --- | --- |
| 连接和教学 JSON 校验 | 200 | JSON 校验通过 | 不写入记忆 | 10.88 |
| 首次错误答案 | 200 | incorrect | suspected | 8.99 |
| 引导后仍错误 | 200 | incorrect | needs_review | 13.99 |
| 引导后纠正 | 200 | correct | improving | 12.51 |
| 另一道不合法序列，解释正确 | 200 | correct | improving | 12.57 |
| 合法序列，操作正确 | 200 | correct | resolved | 12.33 |

同一误区合并到一条记忆，累计五条原文证据。首次错误创建 suspected，重复错误更新为 needs_review，
引导后答对更新为 improving，两道不同题目的首次作答均正确后更新为 resolved。
后续调用均检索到了该记忆；引用均通过当前作答原文校验。

## 观察

- 模型正确区分了“元素集合相同”和“每次弹出当前栈顶”。
- 纠正后的回答得到明确确认，没有将旧错误强加给当前回答。
- 另一题答对后仍要求解释栈顶约束；完整操作序列答对后给出了新的练习。
- 首轮引导同时问了剩余元素、栈顶和能否弹出 1，问题数量可进一步压缩。
- 端到端生成耗时约 9–14 秒，均在当前 45 秒模型超时内。
