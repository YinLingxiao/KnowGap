## 4. 问题

### 问题 1：失败后的「重试」发送上一次提交，不发送刚改过的答案

严重程度：高。模型一旦可用，学生会以为正在提交屏幕上的新答案，实际发出去的是旧答案，诊断和记忆都会对错内容。

复现：

1. API 模式打开 `stack-sequence-001`，答案填「第一版答案」，思路填「第一版思路」，提交。
2. 出现「模型暂时不可用」。把答案改成「第二版答案」，按底部「提交并诊断」。
3. 再把答案改成「第三版答案不应被重试丢掉」，按错误提示里的「重试」。

预期：第 3 步发出第三版。

实际：三次 `POST /api/diagnosis` 的 `answer` 依次是第一版、第二版、第二版。第三次页面上仍显示第三版。`useWorkbench.ts` 的 `retrySubmit` 使用 `lastSubmission`，不读当前输入框。

这不是记忆污染：这次 503 没有写入。记忆列表仍为空。

### 问题 2：未发送的追问草稿在切题后丢失

严重程度：中。答案和思路会按题保存；聊天框不会。

复现（Mock，页面有 Mock 标识）：

1. 第一题提交错误答案，进入当前追问。
2. 在「回复导师」输入「还没发出的追问草稿」，不发送。
3. 打开第二题，再回到第一题。

预期：若与答案草稿同一标准，未发送文字还在。

实际：会话、批注和当前追问都还在，回复框为空。新会话也会清掉这个输入。页面没有承诺保存追问草稿，但和已保存的答案草稿不是同一行为。

### 问题 3：手机上后端断开时，主区看不出失败原因

严重程度：中。

复现：视口 390×844，停掉 8010，刷新 `3010`。

预期：主区说明后端不可用，并给出重试。

实际：主区是欢迎页，「从第一题开始」禁用，可见文字里没有错误。桌面 1280 宽时侧栏有「后端离线」和「无法连接后端服务」，并写明输入已保留。手机目录默认收起，错误在目录里。

### 问题 4：窄屏步骤只剩编号

严重程度：低。

视口窄于 1080px 时，顶栏步骤除当前项外只显示「2」「3」，「批注」「追问」被样式藏掉。功能还在，扫读变差。

## 5. 不能确认的结论

- 真实模型对三道题的对错、信息不足、连续追问、抗诱导，以及看到历史记忆后会不会改问法。本仓库没有模型配置，这些全部是未测。
- 浏览器里一次成功的 API 会话：刷新后的消息、追问失败后的核对重试、40 轮上限。程序测试覆盖了协议和回滚，页面没有成功样本。
- 慢请求下的双击是否仍只发出一次。快 503 期间按钮和其他题目会禁用，这个窗口太短，没有打出第二次请求。
- 键盘、输入法、模型 Markdown 和代码块的显示。
