# KnowGap 前端审阅

审阅版本：Claude 最后版 `5ddcefe`。审阅方式：阅读前端代码，查看最新开发预览的桌面和手机布局。没有运行自动化测试，没有提交答案或调用模型，没有修改页面源代码。真实诊断与追问的视觉状态依据组件代码审阅，未以真实模型结果验证。

## 判断

当前页面有统一的视觉令牌、明暗主题、明确的模拟模式标识，并且“在学生原文上批注”的方向值得保留。但整页仍主要围绕题目列表、表单、聊天记录和记忆记录组织，学习过程中最关键的认知变化没有成为视觉中心。

“一般”的主要原因是：页面空间分配没有随学习阶段变化；中文字偏小、层级接近；首屏用文字解释能力；学习结束和下一步缺乏明确出口。继续更换强调色或圆角很难解决这些问题。

## 其他值得处理的交互

- 模型故障后点击“新会话”，首次作答表单可能保留旧内容：同题 key 未变，表单没有收到 reset 信号。明确“重新作答”是否保留草稿。
- 只有一个最近会话指针，没有会话列表。换题后无法从页面打开之前的推导记录；这是目前产品能力缺口，也涉及后端列表接口。
- `UsedMemories.tsx` 把本地列表中找不到的记录直接说成“已被删除”；记忆列表加载失败时也可能触发。应显示“暂时无法读取”，确认删除后再说删除。
- 题目旁的数字是整个知识点的记忆数。三道同知识点题目显示相同数字，用户容易理解成每题错误次数；数字应有可见说明，或移到知识点分组。
- `ChatComposer` 立即清空输入，失败后只能重试原消息；提供“编辑后重发”能减少修正成本。全文解答快捷按钮从一开始就与提示并列，也应根据学习阶段调整。
- 后端在线状态仅在挂载时检查，可能与后续加载结果不一致。当前错误提示还直接显示 FastAPI、环境变量名等实现细节；开发信息适合收进详情，主提示应给出用户能采取的下一步。

## 建议改版顺序

1. 修好草稿、同题点击、会话重置与旧状态残留，明确未完成会话的恢复方式。
2. 调整页面结构：初始作答集中展示题目和输入；进入教学后突出当前导师问题与学生作答；记忆按需展开。
3. 做出关键体验：原文批注与具体问题相连，栈操作可推导，阶段结束能继续独立验证。
4. 再统一字号、留白、组件层级和明暗主题；最后收敛移动端导航。
